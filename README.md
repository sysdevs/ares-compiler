# ares-compiler

A compiler for RuneScript server scripts, the scripting language of the
[LostCity](https://lostcity.rs) engine. It reads `.rs2` (and `.macro`) source
files, type-checks them against the symbols your engine provides, and writes
the compiled bytecode as a Jag pack (`script.dat` + `script.idx`) or a js5
pack.

It is the script compiler behind
[ares-gameserver](https://github.com/sysdevs/ares-gameserver) and
[runescript-lsp](https://github.com/sysdevs/runescript-lsp). Output is
reproducible byte for byte, and committed snapshots pin every stage.

## Usage

`ares-compiler` is a library. It depends by path on
[ares-shared](https://github.com/sysdevs/ares-shared) (the opcodes, triggers
and type codes it shares with the server), so clone both side by side:

```
git clone https://github.com/sysdevs/ares-shared
git clone https://github.com/sysdevs/ares-compiler
```

Add it as a dependency, along with `indexmap` and `serde_json` for loading
symbols:

```toml
[dependencies]
ares-compiler = { path = "../ares-compiler" }
indexmap = { version = "2", features = ["serde"] }
serde_json = { version = "1", features = ["preserve_order"] }
```

Compile a scripts directory and write a Jag pack:

```rust
use indexmap::IndexMap;
use ares_compiler::runescript::type_info::CompilerTypeInfo;
use ares_compiler::{compile_server_script, Config, WriterConfig};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let symbols: IndexMap<String, CompilerTypeInfo> =
        serde_json::from_str(&std::fs::read_to_string("symbols.json")?)?;

    let config = Config {
        source_paths: vec!["content/scripts".into()],
        symbols,
        writer: WriterConfig::Jag { output: "data/pack/server".into() },
        ..Default::default()
    };

    let output = compile_server_script(&config)?;
    for (_stage, diagnostics) in &output.diagnostics {
        for d in &diagnostics.list {
            eprintln!("{}:{}:{}: {:?}: {}", d.source.name, d.source.line, d.source.column, d.kind, d.formatted());
        }
    }
    if let Some(stage) = output.stopped {
        eprintln!("compilation stopped at {stage:?}; nothing was written");
        std::process::exit(1);
    }
    println!("wrote {} scripts", output.scripts_written);
    Ok(())
}
```

[`compile`](src/runescript/compiler.rs) does the same work without touching
the filesystem: the returned `Output.packs` holds the Jag files, the js5 pack
and every script's raw bytecode (`bin`, keyed by script id) in memory.

For editor tooling, [`analyze`](src/runescript/compiler.rs) parses and
type-checks in-memory `(name, text)` sources without generating code. A
syntax error in one file doesn't stop the others from being checked. The
result keeps the typed trees and symbol tables. `analyze_parsed` does the same
over already-parsed files, and `recheck_file` re-checks one edited file when
its script headers are unchanged (`same_headers`).

### Configuration

| `Config` field | Default | Meaning |
|---|---|---|
| `source_paths` | `../content/scripts` | Directories searched recursively for `.rs2` and `.macro` files. |
| `exclude_paths` | none | Files or directories that are compiled and checked but not written. |
| `symbols` | empty | Engine symbols (see below). `command` and `runescript` are required. |
| `check_pointers` | `true` | Load command pointer metadata and check pointer usage. |
| `features` | all on except `top_level_def_only` | `StrictFeatureLevel`: switches for language features (booleans, procs, macros, enums, structs, dbtables, `&&`/`\|\|`, `calc`, relational `=`, typed queues, pointer inversion, top-level-only `def_`). |
| `writer` | `Jag { output: "./data/pack/server" }` | `WriterConfig::Jag { output }` writes `script.dat` and `script.idx` into a directory; `WriterConfig::Js5 { output }` writes one js5 pack file. |
| `source_names` | `Absolute` | How each script's source file is named in its bytecode: absolute normalised paths, or paths relative to the source directory (`SourceNames::Relative`) for output that is the same on every machine. |

Source directories are walked in bytewise file-name order, and `.macro` files
are read before any script.

### Symbols

The compiler knows nothing about your game data. Ids, names and types come
from a symbol table, usually generated by the engine's packing tools. It is a
JSON object whose keys are symbol kinds and whose values all have this shape
(every field must be present):

```json
{
  "max": 3,
  "map": { "0": "mes", "1": "npc_find", "2": "p_delay" },
  "vartype": {}, "protect": {},
  "require": { "2": "active_player" }, "require2": {},
  "conditional": { "1": true }, "set": { "1": "active_npc" }, "set2": {},
  "corrupt": {}, "corrupt2": {}
}
```

- `map`: id → name. For `constant`, name → value instead.
- `vartype`: id → type name, for `varp`, `varbit`, `varn`, `varo`, `vars`,
  `param` and `dbcolumn` (a comma-separated list for tuple columns).
- `protect`: id → whether writing requires protected access (`varp`, `varbit`).
- `require`, `set`, `corrupt` (and their `2` variants for the secondary
  pointer, plus `conditional`): `command` only. Comma-separated pointer names:
  `active_player`, `active_player2`, `p_active_player`, `p_active_player2`,
  `active_npc`, `active_npc2`, `active_loc`, `active_loc2`, `active_obj`,
  `active_obj2`, `find_player`, `find_npc`, `find_loc`, `find_obj`, `find_db`,
  `last_com`, `last_int`, `last_item`, `last_slot`, `last_targetslot`,
  `last_useitem`, `last_useslot`, `active_invobj`, `active_invobj2`.

Recognised kinds: `command`, `runescript` (script id → `[trigger,name]`),
`constant`, `loc`, `npc`, `obj`, `component`, `interface`,
`overlayinterface`, `fontmetrics`, `category`, `hunt`, `inv`, `idk`,
`mesanim`, `param`, `seq`, `spotanim`, `varp`, `varbit`, `varn`, `varo`,
`vars`, `stat`, `locshape`, `movespeed`, `npc_mode`, `npc_stat`, `model`,
`synth`, `midi`, `jingle`, `hitsplat`, and, when their features are on, `enum`, `struct`,
`dbcolumn`, `dbrow` and `dbtable`.

Command signatures are not part of the symbol table: they are declared in
RuneScript itself (`[command,name](params)(returns)`, usually in an
`engine.rs2` among the sources).

### Output and errors

Compilation runs in stages: parse, analyze (registration and type checking),
code generation, pointer checking, write. Each stage's diagnostics are
returned in `Output.diagnostics`. A stage that reports an error stops
compilation: `Output.stopped` names it and nothing is written. If no command
has pointer metadata, pointer checking is skipped and empty packs are
written.

`Err(CompileError)` is returned for failures that abort compilation outright:
I/O errors, malformed symbols, and source that cannot be compiled at all
(`CompileError::Fatal`, for example a `long` value, which type-checks but has
no bytecode encoding).

## Layout

| Module | Contents |
|---|---|
| `lexer`, `parser`, `ast` | Tokenizer (logos), parser (chumsky) and syntax tree |
| `preprocess` | Macro expansion |
| `types`, `symbol`, `trigger`, `pointer`, `features`, `diagnostics` | Type system, symbol tables, triggers, pointer kinds, feature flags, diagnostics |
| `semantics` | Script registration and type checking |
| `codegen` | Instruction generation and pointer checking |
| `writer` | Bytecode encoding and the Jag / js5 packs |
| `compiler` | Source discovery and the stage pipeline |
| `runescript` | Server-script setup: types, triggers, symbol loaders, command handlers, opcodes |

## Development

```
cargo build
cargo test --release
cargo clippy --all-targets
```

The tests are snapshot gates: each stage (tokens, syntax tree, typed tree, IR,
diagnostics, packs, per-script binaries) is compared with a committed snapshot
under `tests/`. After an intentional output change, re-bless and review the
diff:

```
BLESS=1 cargo test --release --test differential
git diff tests/
```

Commit the inputs and snapshots together, and never hand-edit a snapshot.
[`docs/testing.md`](docs/testing.md) covers the gates, fixtures and corpora.
[`docs/behaviour.md`](docs/behaviour.md) lists every rule that reaches output
bytes; read it before changing one.
